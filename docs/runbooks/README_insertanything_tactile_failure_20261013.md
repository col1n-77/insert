# InsertAnything 触觉 RL：偏角增大与训练退化诊断

更新：2026-10-13。统一索引：[README.md](README.md)。训练入口与历史评估见 [触觉六自由度 RL](README_insertanything_tactile_rl_6d.md)。

本页只针对 `LHole-III` 的 `LHole_III_tactile_inhand10_6d_20261012_233627` 实验。诊断没有改写任务、奖励、控制器或权重，没有重训。新增短控制对照在内存中替换动作来源，结束后关闭仿真。产物目录：

`/data/nju/Lincao/InsertAnything_tactile/outputs/failure_diagnosis_20261013`

## 1. 结论与证据强度

**已经确认的直接原因：第 1000 轮 PPO 策略在实际访问的状态上几乎失去了状态响应，持续给出向上平移和固定方向的旋转。** 触觉传感器没有在这些回合中失去有效接触；轴线转换和执行器可以配合简单的反馈控制减小偏角。

**最强的训练根因线索：自适应学习率过度增长、很大的 KL 更新偏移、网络中间特征接近常量和动作均值严重越界共同出现。** 这是多项相互吻合的证据，但尚未通过“只固定学习率、其余不变”的重新训练证明唯一因果。

**奖励实现也需要调整：5° 宽度的高斯对准项在大偏角区接近零，插入项又乘额外角度门控，接近/半插入奖励也继承了严格角度条件。** 奖励符号和角度单位没有发现反转；问题是偏差变大后，奖励差异迅速变小，难以提供恢复方向。

传感器预测误差是后续精密插入的限制，但现有误差不足以解释约 40° 的整体倾斜。不能把这次失败当成“触觉本身使策略变差”的干净消融结论：两版还有训练预算、动作尺度、夹持几何、Jacobian 和 RNN 序列长度等差异。

## 2. 先区分两种角度

原有完整评估是 16 环境 × 4 个独立测试种子，共 64 回合，每回合 20 秒。逐步保存的物体和 TCP 姿态显示：

| 量 | 初始化 | 结束 |
| --- | ---: | ---: |
| 物体相对夹爪的在手偏角绝对值，均值 | 4.769° | 4.764° |
| 真实物体轴与孔轴夹角，均值 | 4.885° | 39.780° |
| TCP 偏离竖直的角度，均值 | 接近 0° | 39.750° |
| 估计物体轴与孔轴夹角，均值 | — | 39.935° |

因此，这批数据里主要是**夹爪带着物体整体越转越歪**，并非物体在夹爪内的偏角不断增加。触觉网络测的是相对夹爪的单轴角度；即使它保持约 5°，与 TCP 世界旋转组合后，物体相对孔轴仍可能达到 40°。

64 个回合的双侧有效接触比例为 100%（按当前几何接触阈值），在手角度预测 MAE=1.622°、P95=4.556°。世界轴线误差的估计/真值绝对差均值 1.568°、P95=4.514°。网络没有把约 40° 的世界偏差误报成已对准。

## 3. 策略网络具体退化在哪里

完整评估的 19,200 个环境步中，限幅后、EMA 前的确定性动作几乎恒定：

```text
[dx, dy, dz, rx, ry, rz]
[-0.088626, +0.158481, +1.000000, +0.001026, -0.364179, -0.163654]
```

它不能随初始偏角的正负切换纠偏方向。Z 动作始终向上，导致末帧平均深度误差约 +56.72 mm；Y/Z 旋转持续累积，真实轴线误差升高。

本次另采集 4 环境 × 64 步真实策略输入，在 CPU 上用同一份 checkpoint 重放完整 RNN 序列，动作与 GPU 记录最大绝对差仅 `5.96e-8`。因此上述现象不是播放器忘记更新 RNN 状态或简单的输出限幅假象。

- 原始、尚未限幅的 Z 均值约 **7.64473**，动作合法范围是 `[-1, 1]`，执行时变成 +1。
- 原始 Z 输出在该输入序列中的标准差约 `6.74e-7`；最后一层 MLP 特征跨帧标准差的均值仅 `6.32e-8`。
- ELU 中间层在这些输入上大量负向饱和，状态差异被逐层压小；不能据此声称网络在所有可能输入上都恒定。
- 用仿真真值在手角度和相应世界轴线替换触觉输入的五个特征，从第 2 步起重放同一序列，最终 checkpoint 的原始动作变化为 **0**。第 1 步保持原输入以保证初始状态完全一致。这是固定轨迹的输入替换测试，不是重新训练，也不是新的插入成功率评估。
- 较早权重在同一组输入上仍能响应：第 5/50/100 轮，真值特征替换造成的最大动作变化约 0.034/0.094/0.193；第 500 轮已经接近常量。较早权重在这里是离策略探测，不能据此认定它们能成功插入。
- 最终高斯动作标准差是 1.08–2.65，噪声没有随确定性均值退化而消失。Z 维 `mu≈7.645, sigma≈1.515`，随机采样后仍约 99.9994% 会被截为 +1，因此简单改成随机评估无法修复向上动作。

使用的精确 checkpoint：

`logs/rl_games/InsertAnythingTactile6D/LHole_III_tactile_inhand10_6d_20261012_233627/nn/last_InsertAnythingTactile6D_ep_1000_rew__96.08148_.pth`

## 4. 为什么优先检查 PPO 更新稳定性

| 实际训练记录 | 原版，截至评估的第 846 轮 | 触觉版，第 1000 轮 |
| --- | ---: | ---: |
| 最大学习率 | 0.000150 | 0.010000 |
| 末次学习率 | 0.00001317 | 0.006667 |
| 最大记录 KL | 0.03839 | 167.708 |
| 最大原始 bounds loss | 3.079 | 2068.720 |

触觉版第 11 轮学习率已超过 0.001；第 181 轮首次记录到 0.01。第 944 轮出现 KL 和 bounds loss 的最大尖峰。训练回报最早最佳约 175.22，最终约 96.08，没有持续改善。

本机 `rl_games/common/schedulers.py` 的 `AdaptiveScheduler`：KL < 0.5×阈值时将学习率乘 1.5，最高允许 `1e-2`；KL > 2×阈值时除以 1.5。训练配置的阈值是 0.008。当前 `standard` 调度在每个 mini-epoch 后更新学习率，没有因超过阈值而撤销更新或提前停止该轮的代码。

两版虽然继承同一个 PPO 网络，但训练批量不同：原版每轮 128×128=16,384 条、minibatch=512、32 个 minibatch；触觉版每轮 16×64=1,024 条、minibatch=1,024，只有一个 minibatch。仍沿用同一套自适应学习率规则，没有为批量改变设置更保守的上限。日志显示两版学习率实际走向已经完全不同。

`bounds_loss_coef=0.0001` 对越界均值的约束值得一起检查；仅对执行动作做 clip 并不能保证网络本身输出合理。固定学习率是否足以防止退化，仍需独立新实验确认，不能从日志直接给出保证。

证据：`reward_and_training_analysis.json`、`original_training_log_reference.json`；上游实际调度代码路径记录在 `manifest.json`。

## 5. 奖励问题是过窄、叠加门控，不是符号相反

当前对准项：`exp(-(alpha/5°)^2)`。插入奖励额外乘 `exp(-(alpha/10°)^2)`，其中 alpha 是估计世界物体轴与孔轴的夹角。

| alpha | 对准项，sigma=5° | 插入项角度乘数，sigma=10° |
| --- | ---: | ---: |
| 0° | 1 | 1 |
| 5° | 0.3679 | 0.7788 |
| 10° | 0.01832 | 0.3679 |
| 15° | 0.0001234 | 0.1054 |
| 20° | 1.13e-7 | 0.01832 |
| 40° | 1.60e-28 | 1.13e-7 |

在偏离 20–40° 后，往正确方向转一点和继续转歪，对该奖励的影响都极小。PPO 不对奖励公式直接反向传播，但它同样需要动作导致可区分的回报变化。

插入项还同时受 XY 指数门控和 yaw<5° 条件限制。此外，原代码通过 `_get_curr_successes()` 同时计算接近、半插入和完成；触觉子类重写这个方法后，三种阶段奖励全都要求估计轴线 <3°、有效接触和深度下界。严格完成条件被提前用于接近阶段，进一步减少了训练初期反馈。

逐项重算原有 19,200 个环境步的奖励，与保存的总奖励最大误差 `3.07e-7`（排除无法从旧日志恢复前一动作的首步）。结果：

- 65.17% 的状态，对准项小于 `1e-4`。
- 每步平均 z_insert 只有 0.002113；即使只去掉新增角度门控，同一批轨迹也只有 0.005555，说明 XY/yaw/高度本身也没有学好。
- 结束时平均对准项约 `3.32e-13`，插入项约 `5.97e-9`；剩余正回报主要来自 XY 和 yaw 的部分接近程度。
- 接近、半插入、完成奖励在这批轨迹中均为 0。

这不表示“越歪奖励越高”，也不证明坏姿态是全局最优；它说明坏姿态附近的纠偏信号太弱。单独把 5° 项的权重从 1 改到更大，无法有效解决指数尾部接近零的问题。

实现：`source/insertanything_tactile/rl/env.py` 的 `_get_curr_successes()` / `_get_factory_rew_dict()`，参数在 `source/insertanything_tactile/rl/config.py`。

## 6. 短时物理对照：传感器能否正确驱动纠偏

本次保持同一触觉资产、初始化范围和控制器，用 seed=1001，4 环境，每种动作来源运行 64 步（4.267 秒），没有执行插入策略训练。后续模式重新物理抓取，初始姿态存在小差别，表中分别报告初值。

| 动作来源 | 初始真实轴误差均值 | 结束真实轴误差均值 |
| --- | ---: | ---: |
| 第 1000 轮策略 | 3.632° | 8.377° |
| 零动作 | 3.708° | 3.477° |
| 触觉预测轴线 + 比例纠偏 | 3.708° | 1.858° |
| 真值轴线 + 同一比例纠偏 | 3.708° | 1.113° |

比例纠偏仅使用世界轴线叉乘：`delta_rotation = 0.08 * cross(object_axis, hole_axis)`，再除以原旋转动作尺度并限幅至每轴 ±0.3；平移动作保持零。没有移动物体来伪造结果。

四种模式双侧触觉均有效。这支持：姿态坐标/符号转换、6D 执行方向以及当前物理抓持可用于纠偏。触觉版仍有估计残差：例如一个环境最终估计轴误差约 0.93°，真实约 3.37°。因此，当前角度网络能用于方向反馈，但并未证明足以可靠满足 3° 的最终公差。

这些短对照不包含完整插入，不能把 1.86° 的结果当成成功率。它们也没有排除所有动态接触、噪声和长期滑移问题。数学/估计器相关的 5 项现有单元测试通过。

## 7. 建议修复顺序与待验证项

1. **先稳定优化过程。** 新建实验，从头训练以获得清楚的对照；先用固定 `1e-4` 或更保守的学习率，actor/critic 都核对；监控 KL、原始动作均值、clip 比例和状态响应。不要直接把这份第 1000 轮权重当作健康起点继续追加轮次。学习率数值是下一轮的起点建议，尚未验证其插入成功率。
2. **再增加大偏角下的奖励差异。** 保留原位置/yaw 的连续奖励，对轴线采用宽范围项加精细项，例如约 20° 的粗对准高斯与 5° 精对准高斯，或有界的连续角度代价。最终完成继续严格检查 3°，但接近/半插入使用独立阶段条件，避免所有阶段都过早要求精确对准。门控宽度和奖励尺度需通过短实验验证，不能仅提高最终成功奖励。
3. **在同一触觉硬件和控制设置下做消融。** 真值角度输入/真值角度奖励作为诊断上限；再换成预测输入但保留真值奖励，最后换为预测输入与预测奖励。真值仅用于定位问题，不把它当成可部署触觉策略。此顺序区分优化、观测误差和奖励误差。
4. **统一训练预算及有效记忆。** 两版用相同的累计环境转移数比较。原版第 846 轮已有 13,860,864 条，触觉第 1000 轮只有 1,024,000 条；1000 轮并不等价。触觉 seq_length 从 128 缩至 16，使反传序列从约 8.53 秒缩至 1.07 秒，这是额外混杂因素。RNN 执行时状态仍可跨序列保留，不能把 seq_length 简化成硬性的记忆时长。
5. **优化最终角度精度。** 当前 P95=4.56° 超过 3° 成功公差。需要对接近对准时的数据和实际受力状态做误差分析，避免模型误差导致奖励误判；不应拿平均 MAE 直接保证精密插入。

还需保持清楚的配置差异：原版平移/旋转动作尺度 0.02 m / 0.097 rad，触觉版 0.003 m / 0.035 rad，并额外限制旋转向量范数；触觉版使用 mesh center 抓持锚点、TCP 对应的 Jacobian 和附加观测。上述差异有其设计目的，当前短对照没有显示执行方向错误，但不能混在一次实验里归因为传感器效果。
